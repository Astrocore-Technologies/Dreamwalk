# NPC AI: безопасная эксплуатационная граница

## Что включено сейчас

По умолчанию `NpcAiService` использует локальный mock, цена и провайдерский бюджет равны нулю. Автономные игровые рутины не вызывают модель. Настоящие API, покупка валюты и изображения **не подключены и не проверялись платными запросами**. Тесты HTTP-адаптера используют подставной локальный transport; интеграционные тесты — отдельный PostgreSQL.

Планировщик получает только серверно отфильтрованные знания NPC. Отдельный запрос публичной речи получает только разрешённые утверждения и фактическую аудиторию; закрытая память планировщика туда не переносится. Summary является производной от доказательств и проверяется ядром. Никакой ответ модели не исполняется как JavaScript/SQL. Изменения мира и списание резервов совершаются в одной транзакции runtime после повторной авторизации и проверки read set.

## Настройки будущего внешнего провайдера

Это отдельные серверные `NPC_AI_*` параметры, не клиентские настройки. Платформенный `AI_PROVIDER` и платежные флаги остаются в прежнем mock-режиме. Следующие значения описывают интерфейс, а не разрешают включение платных вызовов:

| Переменная                                            | Безопасное значение по умолчанию / назначение                                 |
| ----------------------------------------------------- | ----------------------------------------------------------------------------- |
| `NPC_AI_PROVIDER`                                     | `mock`; иной вариант `http-json`                                              |
| `NPC_AI_EXTERNAL_APPROVED`                            | `false`; только после отдельного согласования бюджета и провайдера            |
| `NPC_AI_ENDPOINT`                                     | отсутствует; точный HTTPS endpoint доверенного сервера                        |
| `NPC_AI_ALLOWED_ORIGINS`                              | пусто; список точных origin через запятую                                     |
| `NPC_AI_API_KEY`                                      | отсутствует; только серверное хранилище секретов                              |
| `NPC_AI_MODEL`, `NPC_AI_VERSION`                      | оператор выбирает модель и версию договора                                    |
| `NPC_AI_COST_CEILING_ATTESTED`                        | `false`; оператор подтвердил, что endpoint соблюдает переданные лимиты        |
| `NPC_AI_UPPER_MICROS`, `NPC_AI_CAP_MICROS`            | `0`; верхняя оценка запроса и общий провайдерский лимит в целых микроединицах |
| `NPC_AI_CREDIT_PRICE`                                 | `0`; отдельная заранее показанная цена операции в демонстрационных Искрах     |
| `NPC_AI_TIMEOUT_MS`                                   | `8000`, допустимо 100–60000                                                   |
| `NPC_AI_MAX_INPUT_TOKENS`, `NPC_AI_MAX_OUTPUT_TOKENS` | 16000 / 1024; передаются endpoint как обязательные ограничения                |
| `NPC_AI_KILL_SWITCH`                                  | `false`; `true` блокирует новые запросы и применение ответов                  |

`http-json` — **не утверждение о совместимости с OpenAI API**. Запрос содержит `model`, `purpose`, `context`, `operationId` и `limits`; ответ содержит `proposal`, `requestId`, `usage:{inputTokens,outputTokens,costMicros}`. Для выбранного реального провайдера потребуется подтверждение договора/адаптер и отдельный разрешённый smoke test. Выбор http-json без explicit approval оставляет внешние вызовы выключенными. Неполная разрешающая конфигурация не запускается.

URL не задаётся игроком. Запрещены IP literals (включая IPv6), credentials, query/hash, localhost/local/internal и редиректы. Exact allowlist — граница доверия к серверному оператору, **не DNS pinning и не универсальная защита от смены DNS доверенного домена**. Оператор обязан контролировать endpoint и его DNS/egress. Текст ошибок не содержит ключ, запрос, ответ или память.

## Состояния и деньги

Долговечная задача проходит `reserved → running → result_received → committed`; возможны `stale`, `cancelled`, `failed`, `reconciling`. Значения queued/validated предусмотрены схемой, но отдельного обязательного сохранённого шага не требуют. Один живой запрос NPC ограничен SQL unique index; claim сериализуется advisory lock кампании, в кампании одновременно выполняется один provider request. Повтор operation ID с тем же публичным намерением возвращает прежний DTO даже при изменившемся мире; смена канала речи/адресата/согласия конфликтует.

Quote действует ограниченное время, используется один раз, а выдача ограничена 60 запросами пользователя в минуту. Wallet.balance не уменьшается при резервировании; доступно `balance − held`. Любые старые административные списания учитывают held. Capture добавляет ledger с уникальным source key и применяется ровно один раз. Ошибка, stale, отзыв доступа или истечение резерва освобождает hold; поздний результат не создаёт новое согласие и не списывает валюту. Принятый cache hit повторно не оплачивается; ключ включает кампанию, NPC, purpose, полный context fingerprint, версии модели и policy.

Провайдерский учет независим: `reserved + spent + unknown ≤ cap`. Непонятный исход сети учитывается как unknown на всю верхнюю оценку, а не как бесплатная ошибка. Нет слепого автоматического повтора. Реальный отчёт выше верхней оценки записывается полностью на задаче; `overrun` хранит превышение отдельно, breaker блокирует весь provider ID. Это учётный hard cap, **не гарантия, что сторонний сервер физически не выставит неверный счёт**. Отмена пользовательского списания не стирает стоимость провайдера.

`reconcile(jobId,eventKey,actualMicros|null)` — внутренний операторский метод, не игровой endpoint. Он требует подтверждённого результата и идемпотентного ключа. При превышении лимита часть до upper относится в spent, превышение остаётся в overrun; breaker не снимается автоматически. После изменения финансовой политики оператор должен разбирать инцидент, пересчитать лимит/расход и отдельно разрешить возобновление. Простая смена версии/рестарт не сбрасывает счётчики. `GET /api/v1/admin/npc-ai/metrics` требует действующую администраторскую сессию; внутренний `metrics()` возвращает только агрегаты состояний/возраст и бюджетные счетчики, без prompts/секретов/личных идентификаторов. Дополнительно возвращаются средняя/максимальная задержка последних 10 000 результатов, число hot observations, причин в очереди и активных обязательств в выборке первых 1000 кампаний, а также число архивных эпизодов. Размер выборки указан явно; каждый SQL-запрос ограничен statement timeout 2 секунды. Это ручная диагностика администратора, не опрос на каждом игровом tick.

## Пауза, рестарт, отзыв доступа и удаление

При всех игроках offline новые provider requests не стартуют и готовые результаты не изменяют мир. Уже отправленный запрос может завершиться и сохраняется; применение ждёт возвращения, повторной авторизации и проверки контекста. Технические сетевые timeout и время финансового резерва остаются wall-clock: фоновая bounded maintenance освобождает просроченные holds даже без игровых ticks. Это не продвижение игрового времени.

После аварии сохранённый running не запускается повторно. По истечении deadline задача становится reconciling; выяснение расхода не зависит от присутствия игроков. Изменение policy/provider version делает ещё не отправленный запрос stale. Отзыв членства/доступа к исходному произведению помечает задачи долговечно, поэтому revoke→reinvite не оживляет старый план. SQL triggers аннулируют cache соответствующей кампании. Повторная авторизация непосредственно перед commit остаётся обязательной.

Удаление данных обнуляет приватные context/proposal/cache и персональные ссылки, освобождает hold, но сохраняет консервативные spent/unknown и обезличенные финансовые записи. Уже отправленный запрос без доказанного результата остаётся потенциальным расходом. Экспорт возвращает пользователю только метаданные его задач, не память другого NPC/игрока.

## Проверки

`GAME_TEST_FILE=integration-ai-orchestration.test.mjs npm run test:game:integration` поднимает отдельный локальный PostgreSQL, не трогая preview. Проверяет конкурентные резервы, защиту admin debit, rollback/capture/replay, неизвестный исход, restart, поздний ответ, pause, технический expiry, версии, cache, revocation/erasure, breaker/reconciliation и подставной HTTP transport. Сквозные маршруты планирования/summary/речи дополнительно проверяются runtime suite. Живой провайдер, его фактическая тарификация и качество речи остаются отдельным этапом после разрешения пользователя.
