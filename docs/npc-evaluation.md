# Воспроизводимая оценка живых NPC

## Что проверяет этот набор

`scripts/evaluate-npc.mjs` запускает **реальное скомпилированное game-core**, без
БД, сети, внешней модели и платных запросов. Он проверяет семь заранее определённых
поведенческих критериев и выполняет небольшой ограниченный замер локального ядра.
Это проверка детерминированных mock-механизмов, **не оценка естественности речи LLM**.

Перед запуском актуальная сборка обязательна:

```sh
npm run build -w @dreamwalk/contracts
npm run build -w @dreamwalk/game-core
node scripts/evaluate-npc.mjs
```

Не запускать повторную сборку параллельно с другим сборщиком. Сам скрипт ничего не
пересобирает, не изменяет исходники и не открывает сервер. JSON-отчёт пишет в stdout;
для сохранения можно перенаправить его в локальный файл, не добавляемый в Git.

## Фиксированная рубрика

| Критерий                  | Сценарий                                                             | Условие успеха                                                                                                             |
| ------------------------- | -------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| Характер                  | Одно обращение к одинаковым NPC с профилями Cookie и Green Apple     | Cookie предлагает помощь, Green Apple не превращается в помощника вопреки заданному профилю; модель провайдера не меняется |
| Персональные отношения    | NPC видит действие Alice при наличии Bob                             | Изменение относится к Alice, а не ко всей группе                                                                           |
| Ограниченное знание       | NPC отвлечён, Bob забирает предмет                                   | Позднее обнаруживается отсутствие без придуманного виновника                                                               |
| Исправление убеждений     | Ложный слух о Bob противоречит прямому наблюдению Alice              | Слух сохраняется как источник, ошибочное убеждение получает disputed                                                       |
| Обещание и восстановление | Условное принятое обещание, сериализация/восстановление, ход времени | Передаётся ровно один существующий предмет правильному участнику, статус fulfilled                                         |
| Обоснованная память       | В корректное резюме подставляется выдуманный рассказ                 | Подмена отклоняется; исходные свидетельства не изменяются                                                                  |
| Подтверждение намерения   | Текстовое предложение взять предмет                                  | До явного подтверждения нет эффекта; после него действует обычный серверный reducer                                        |

Каждый критерий имеет результат pass/fail и исполняемые assertions. Нельзя
интерпретировать семь pass как «7/7 по человечности». Промежуточные причины и
состояния проверяются непосредственно, а не только по итоговому тексту NPC.

Полный набор `tests/game/core*.test.cjs` дополнительно проверяет шёпот, приватные
вопросы и факты, все обещания вне ограничения контекста, отмену планов, поздние
ответы, профили, условия и альтернативы, формирование раундовых намерений без
чужих будущих действий, а также движение на границах видимости. Сценарий
восстановления в этом скрипте — сериализация JSON. **Реальный crash/restart БД**
проверяется отдельным PostgreSQL integration suite, а не приписывается этому тесту.

## Ограниченный локальный замер

Параметры:

```sh
node scripts/evaluate-npc.mjs --campaigns 4 --ticks 100 --runs 3
```

Разрешены 1–16 кампаний, 1–300 шагов на кампанию и 1–5 повторов. В каждой кампании
один автономный NPC и два игрока. Игроки не генерируют поток команд: это **тихий
baseline рутины и сохранённого состояния**, не нагрузка боёв, длинных диалогов или
активного редактирования. Перед измерениями выполняется отдельный прогрев.

Замер 30 октября 2026 года, Node v24.22.1 (x64, 9 логических CPU), с указанной конфигурацией:

| Показатель                      |       Фактический результат |
| ------------------------------- | --------------------------: |
| Поведенческая рубрика           |                 7 из 7 pass |
| Число повторов                  |                           3 |
| Кампаний на повтор              |                           4 |
| Шагов на кампанию               |                         100 |
| Всего измеренных шагов кампаний |                       1 200 |
| Время повторов                  | 70,591 / 66,568 / 68,990 мс |
| Сумма измеренного времени       |                  206,149 мс |
| Среднее на шаг одной кампании   |                 0,171791 мс |
| CPU user / system               |         266,331 / 12,761 мс |

Время CPU может отличаться от wall-clock из-за работы среды выполнения. Значения
зависят от прогрева, соседней нагрузки и оборудования. Это **не заявленная
производственная ёмкость**, не обещание числа одновременных кампаний и не оценка
стоимости API. Здесь не измеряются PostgreSQL, сетевые очереди, WebSocket,
браузерный renderer или несколько writer-процессов.

JSON-отчёт содержит timestamp, точную версию Node, архитектуру, количество
логических CPU, параметры и SHA-256 четырёх реально загруженных compiled-модулей.
Это позволяет отличать результаты разных сборок. Повторяемость означает одинаковые
игровые результаты и assertions; миллисекунды не обязаны совпадать.

## Отдельный gate реального провайдера

До подключения платной модели остаются явное разрешение владельца, выбранный
провайдер, допустимые данные и финансовый cap. Затем на **тех же сюжетных fixtures**
нужна отдельная человеческая оценка: объяснимость реакции, устойчивость характера,
память значимого, отсутствие лишнего знания, собственная инициатива и понятность
последствий. Результаты следует сохранять вместе с моделью/версией policy,
задержками, usage, фактической стоимостью и rejected/stale outcomes.

Текущие pass не заменяют эту проверку и не доказывают качество естественного
диалога. Воспроизводимый mock и строгие инварианты — основание для неё, а не
подмена реального испытания.
