# Authentication visual alignment

The sign-in, registration and password-request compositions use the approved
desktop sign-in reference (35). The bundled `auth-portal.webp` is a standalone
illustration generated with the built-in image tool using that mockup as a visual
reference: silver-haired fictional traveler, white cat, glowing celestial portal,
moonlit bridge, telescope and books. The prompt explicitly excluded text, logos,
form controls and the right-hand UI panel. The generated image was inspected and
encoded as WebP; no runtime image provider is required.

The full-height art and form share the selected proportions. The brand overlays
the artwork; language and theme controls remain reachable. Input icons, a keyboard
operable password visibility button, gold outlines and centered secondary links
follow the design. Semantic labels, form POST handling, autofill, validation,
Google-provider availability, local-preview aliases and safe story-return intent
remain intact. Existing truthful early-access/legal copy is retained. Token-based
email confirmation/reset screens do not receive the full-screen form overlay.

Synthetic CI scenarios capture all three form routes at desktop/mobile in both
themes and across RU/UK/EN, assert image loading and no horizontal overflow, and
exercise password toggling plus signup/reset/Back navigation without submission.
These are implementation evidence, not production screenshots or pixel-identical
acceptance of every page. Full CI and independent screenshot review are required.
