# Location-only encounter admission

Coordinate-free scenes use explicit canonical encounter membership, not map equality or invented distances. Public narration is scoped to the server-stamped audience. Unscoped legacy canon is not location-only evidence. Narration spanning a location change is actor-only because its prose can include both source and destination information.

An existing source NPC may enter an encounter only when the trusted compiler marked their opening presence genuinely unresolved. The marker binds the original map, singleton scene and immutable source checksum. Typed authored assignments, separately assigned hidden/offstage groups, another map, changed source/life/scene fingerprints, and missing markers are ineligible. The planner must explicitly designate genuinely unspecified presence; the field defaults to false. That designation is a semantic interpretation of the source, not a deterministic proof that prose never describes absence or concealment. The immutable package admission verifies and binds provenance before runtime use.

Only a director request containing an actual attempt segment receives up to eight qualified opaque candidate tokens and fingerprints. Candidates have no names, source IDs, character roles, appearance, biography or private lore. They are internal planner input, not a public roster, UI list or error detail. A token is not proof that an encounter has occurred.

The already-priced director call interprets the player's intent and public source constraints. It must respect negation, hypotheticals, quoted speech, absence and concealment. The reducer proves structural attempt binding, compiler provenance, current fingerprints and one atomic outcome. It does not claim to deterministically understand natural-language entailment; tests inject typed proposals and do not establish real-provider comprehension. Opaque candidates also cannot guarantee resolution of a particular named character among several unknown candidates. Named intent, negation and prose-only concealment are explicit live-QA cases, not verified capabilities.

Admission moves the existing NPC into the player's explicit encounter, clears unresolved provenance, records witnessed presence without coordinates, and stores the actual NPC ID with the internal request token and fingerprint for exact replay. The only newly admitted narration is a typed encounter summary using the now-established public identity. An ungrounded quote of that NPC in the same turn is rejected. Ordinary subsequent dialogue uses the existing safe speech context. There is no second provider call, automatic paid retry or synthetic movement.

Tests: `tests/game/core-location-only-dialogue.test.cjs` covers source-qualified encounter followed by dialogue, opaque candidate privacy, invalid provenance/source/life/scene/map, ordinary quoted speech, same-turn invented voice rejection, and exact replay, alongside scene audience and legacy-position behavior.
