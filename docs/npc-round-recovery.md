# NPC round decisions and recovery

Every living, active NPC on a player-occupied map receives one private model
consideration per world round, including rounds with no player speech. Prior plans,
obligations and cognition remain decision context; they no longer skip a model turn.
An already agreed off-map companion crossing remains a bounded mechanical action,
not permission to simulate a dormant off-map mind.

## A blocked intention is not an unknown provider outcome

A schema-valid, correctly fenced model decision can choose an action the engine
cannot perform, for example a whisper to a distant NPC. The engine must reject that
action without discarding the entire successful model consideration or stranding
its known usage in failure-policy review.

The runtime first uses the existing strict plan admission. If it fails and the
frozen world-round actor/map/brain identity is still current, it revalidates the
original proposal envelope and cognition with a safe wait and no belief revisions.
Only if that independent core validation succeeds does it commit the consideration,
clear the executable plan and retain a private blocked outcome for the next round.
No forbidden action, invented item, disclosure or belief change is applied. The
normal one-job settlement captures its measured usage under the accepted quote;
it does not dispatch a retry. The native result code records the blocked intention.

Malformed results and stale round, entity, map, brain, deadline or future-knowledge
fences still fail. Genuine unknown cost, unpriced usage, overruns and existing pending
holds retain their existing accounting protections. Existing pending financial
records are not automatically rewritten by this change. A separate owner-only
[known-cost settlement endpoint](known-npc-settlement.md) supports explicit,
amount-bound recovery through the existing accounting helper.

Planner context explicitly lists adjacent communication recipients and complete
prospective say/whisper audiences. Acoustic speech still reaches the actual heard
area; selecting a person does not exclude nearby listeners.

## User visibility

The game shows the owner's current Sparks and Dreams balances. A read-only forecast
updates during the player phase, and the complete exact quote is prepared when the
world batch is available. A forecast is not consent, a reservation or a provider call.
Exact quotes still require explicit consent. Unresolved prior billing stays visible
in the player phase instead of appearing as silent NPC behavior.

Verification uses synthetic fixtures and mocked providers. No production gameplay,
provider dispatch or accounting reconciliation is part of a test run.
