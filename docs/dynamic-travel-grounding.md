# Generated travel map grounding

A generated illustration is not proof that its requested coordinate template was followed.
New illustrated travel therefore prepares a compound quote: the unchanged narrative and
image requests plus an explicit bounded future-raster grounding tranche. One confirmation
accepts all three. Existing-location travel and ordinary roleplay keep their existing rules.

The future tranche is not presented as an already exact request. It authorizes one raster,
one operational exact-token-count request and one vision generation, under fixed provider,
model, pricing, source, policy and token/reserve ceilings. The aggregate fingerprint covers
the whole envelope and native request identities. After the image is admitted, its exact
revision and SHA-256 enter a frozen native context and body snapshot. Over-ceiling work is
rejected before vision generation. Unknown counts or provider outcomes are not retried.

The existing native authoring engine provides reservations, quote proofs, queueing, dispatch,
usage and settlement. The exact-count receipt is durably linked before its external call;
successful receipts are reusable after restart and cache expiry. Lost SQL replies reconcile
only the identical successful receipt, never an uncertain provider request. Native enqueue
and its travel-stage linkage commit in one transaction. Historical approval is not expanded.

The vision result must identify the exact image, meet the existing 0.85 confidence floor,
provide a 24 by 24 observation raster, four proven spawn cells, a return point and every
actual arriving actor's footprint. Unknown cells remain unknown. Actor footprints cannot
overlap and must be in the same observed floor/door component. Source, roster, permissions,
image identity and native consent are rechecked before atomic scene admission. Invalid
geometry cannot partially create the destination or teleport offstage actors. Artwork and
map coordinates become available together. This does not change movement collision rules.

Confirmed erasure removes duplicate private grounding context and cancels undispatched
work while preserving uncertain financial liabilities.

## Local verification

The focused grounding suite covers image identity, uncertainty, confidence, connectivity,
footprints, roster preservation, bounded quotes, mutated consent, count authorization,
durable replay and lost successful-count replies. The disposable PostgreSQL travel suite
uses synthetic image/text transports only and exercises one-confirmation arrival, restart,
quote expiry, private independent arrivals, invalid admission, erasure and uncertainty.
Actual paid-provider accuracy and deployment are not exercised by these tests.

Local verification on 2026-11-05: API build and web typecheck passed; changed-file ESLint
and whitespace checks passed; focused suites passed 99 checks before the additional
companion-roster case (the grounding suite now passes 41); disposable PostgreSQL travel
passes all 12 checks, including lost count-commit/readback and native-enqueue replies.
No browser flow was run in this storage-constrained environment.

A crash before native enqueue that outlasts the native quote's 60-second expiry fails
closed. It does not silently create another quote/count or relax wallet expiry. A committed
native job survives expiry of its original quote and reuses its existing reservation.

Spatial review follow-up: revisits and fixed-exit transitions now share an admission-only
predicate. It requires the current background revision and SHA-256, connected observed
floor for the entire arriving footprint, and the existing occupancy/encounter checks.
Crowded spawn cells can fall back only to other verified floor in that component. A player
without space fails without moving; a companion without space stays behind. Ordinary
movement and pathfinding are unchanged.

Validated placement and its exact image binding are applied to the local story draft before
arrival observations or memory are recorded. The commit transaction repeats all authorization,
image and roster checks before pinning. A positive two-companion regression verifies newly
seen coordinates come from the grounded result, not the provisional scene template.
